## 3. Angular 空值问题

现场导入失败时出现过“Angular 为空”的情况。

已对照 M90 处理方式：M90 会读取 `Angular` 列，但 GPS 角度校验只在角度非空、不是 `n` 且 `IfAngle=是` 时执行。因此 Android11 已调整为：

1. `Angular` 列缺失仍报错。
2. `Angular` 值为空允许导入。
3. 非空但格式非法仍报错。
4. `Longitude` / `Latitude` 仍然必填。

已补单元测试覆盖空角度允许导入。

## 4. RS485-2 / JHY 客流

5 月 18 日旧日志反馈的问题是独立问题：RS485-2/JHY 收、发和首页显示“时好时坏”，不是现场英文资源包本身导致。

当前 Android11 已补：

1. RS485-2 对应 M90 口位 `ttyS9`。
2. `config.csv` 能把 RS485-2 切到 `JHY @ 9600`。
3. JHY 查询帧、回包解析和首页 `FIN/FOUT/BIN/BOUT/ALL` 绑定已接入。
4. 兼容日志里真实出现的 JHY 回包格式。
5. `M90ManagedJhySerialPortAdapter` 对 native JNI 不匹配增加兜底，避免 `UnsatisfiedLinkError` 直接崩溃；native 不可用时回退统一串口适配链。

真机测试仍要确认：

1. RS485-2 实际是否为 `ttyS9 / 9600`。
2. 协议是否为 `JHY`。
3. TX 是否稳定发送查询帧。
4. RX 是否收到客流设备回包。
5. 首页计数是否随解析结果刷新。

## 5. 英文资源与页面

切换英文后仍有中文的原因主要有两类：

1. 部分旧界面字符串没有英文资源覆盖。
2. 部分页面在 Java 里硬编码中文选项，而不是从资源文件读取。

今日已处理：

1. 在 `app/src/main/res/values-en/strings.xml` 补入一批旧页面英文字符串。
2. 补入旧串口相关数组英文显示项。
3. 外设设置页协议和串口下拉改为“英文显示、内部保存原值”。

例如界面显示 `Tongda`，保存到配置仍是 `通达`；界面显示 `None`，保存仍是 `无`。这样不会影响协议判断和现场配置。

后续如果仍看到中文，优先判断是：

1. 资源缺英文翻译。
2. Java / layout 写死中文。
3. 业务数据本身来自 `SourceFile` 的中文站名或线路名。

今日已验证：


均已通过。

Debug 测试包路径：

`app/build/outputs/apk/debug/app-debug.apk`

今日用户执行 release rebuild 后已生成：

`apk/release/APP20260602202324.apk`

该 release 包可直接给测试安装验证。

`sh apk.sh rebuild --pin-base` 报“同一 versionName=0.1.1 已存在不同内容的基线”是脚本保护，不是构建失败。原因是旧基线里已有 `apk/base/base-0.1.1.apk`，但今天新包内容不同且仍叫 `0.1.1`。

处理建议：

1. 只是测试完整包：直接安装 `apk/release/APP20260602202324.apk`。
2. 要作为新现场基线：优先升级 `versionName`，再执行 `sh apk.sh rebuild --pin-base`。
3. 已确认设备切到今天这版完整包，并要强制重钉基线时，执行 `sh apk.sh rebuild --pin-base --force-pin-base`。

## 7. 测试建议

测试现场英文资源包时，按下面顺序：

1. 安装今天 release 包。
2. 清应用数据或卸载重装，避免旧 Tinker patch 和旧运行配置干扰。
3. 导入现场 `SourceFile.zip`。
4. 查看导入诊断和日志，确认 `Angular` 空值不再失败。
5. 查看配置或外设设置页，确认 `RS485-2=JHY`、波特率 `9600`、语言英文。
6. 重启应用后确认英文界面和线路列表。
7. 连接客流设备后看 RS485-2 TX/RX 日志和首页计数变化。
