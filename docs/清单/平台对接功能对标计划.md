## 二、关键差异详解

### 2.1 平台文本消息（0x8300）【P0 - 紧急】

#### 现场版实现（MainActivity.onSocketRead808Response）

**消息结构：**
```
消息体首字节flag定义（8位）：
- bit0: 紧急标志
- bit1: 终端显示
- bit2: TTS播报
- bit3: 中心导航信息
- bit4-7: 保留
```

**处理流程：**
1. 解析flag判断消息属性
2. 存储到MessageModel数据库
3. 根据flag.bit1触发界面显示（MessageFragment）
4. 根据flag.bit2触发TTS播报（SystemTTS.playText()）
5. 发送0x0001通用应答

**关键代码位置：**
- `MainActivity.onSocketRead808Response(4, hexData)` - 约第3181行开始
- `MessageModel` - 数据库存储
- `SystemTTS.playText()` - TTS播报

#### Android11现状

**已实现：**
```java
// Jt808TextMessageCommand.java
public static final int FLAG_DISPLAY = 0x04;  // bit2: 展示
public static final int FLAG_SPEAK = 0x08;    // bit3: 播报

// DispatchBusinessModule.handlePlatformTextMessage()
if (command.shouldDisplay()) {
    publishPlatformText(command.getContent());  // 首页展示
}
if (command.shouldSpeak()) {
    playDispatchNoticeIfPossible(command.getContent(), ...);  // TTS播报
}
sendPlatformGeneralResponse(...);  // 通用应答
```

**音频路由：**
```java
// LegacyStationAudioUseCase.playDispatchNotice()
enablePinsLocked(shellConfig, true, false, true);
// inner_audio=1, outer_audio=0, inner_speaker=1 （内音+小喇叭）
```

#### 差异与缺失

| 项目 | 现场版 | Android11 | 差异 |
|------|--------|-----------|------|
| flag位定义 | bit0-3有定义 | 只用bit2/bit3 | **缺失bit0紧急标志、bit3导航信息** |
| 消息存储 | MessageModel数据库 | 仅内存状态 | **缺失数据库持久化** |
| 消息查看入口 | MessageFragment页面 | 无专门页面 | **缺失消息查看功能** |
| 司机/乘客区分 | 未明确实现 | 未实现 | **需求新增功能** |
| RS485转发 | 未发现代码证据 | 未实现 | **需求新增功能** |
| 音频路由 | 应为小喇叭（司机） | 内音+小喇叭 | **需修正为小喇叭** |

#### 修复计划

**阶段1：对齐现场版（P0）**
1. 补全flag位定义（bit0紧急标志）
2. 实现MessageModel数据库存储
3. 创建消息查看页面（MessageFragment）
4. 修正音频路由为小喇叭

**阶段2：扩展新需求（P0）**
5. 扩展flag支持司机/乘客区分（bit4/bit5）
6. 实现乘客端RS485转发逻辑
7. 实现乘客端内音播报

### 2.2 设置终端参数（0x8103/0x8900）【P1】

#### 现场版实现

**支持的参数类型（0x8900透传）：**
```java
type 12: 心跳间隔（秒）
type 13: GPS上报间隔（秒）
type 14: 超速上报间隔（秒）
type 15: 超速阈值（km/h）
type 16: 急加速阈值
type 17: 急减速阈值
type 18: 急转弯阈值
type 19: 怠速阈值（分钟）
type 20: 最大停车时间（分钟）
type 21: TTS音量（0-15）
```

**处理流程：**
1. 解析透传消息type值
2. 更新SharedPreferences对应配置项
3. 动态应用到运行时：
   - 心跳间隔：重启定时器
   - GPS间隔：调整上报频率
   - 超速阈值：更新监控参数
   - TTS音量：调整AudioManager音量

#### Android11现状

```java
// DispatchBusinessModule.handleSocketFrame()
if (messageId == MSG_SET_TERMINAL_PARAMETERS || (messageId & 0x8000) == 0x8000) {
    dispatchState.markPlatformResponse(messageId, true);  // 只记录，未应用
}
```

**问题：**
- ❌ 没有解析参数内容
- ❌ 没有更新ShellConfig
- ❌ 没有动态应用到运行时

#### 修复计划

1. 实现`Jt808ParameterParser`解析0x8103/0x8900参数
2. 映射到ShellConfig对应字段
3. 实现参数动态应用机制：
   - 心跳间隔 → 重启socketReportExecutor
   - GPS间隔 → 调整GPS监听器
   - 超速阈值 → 更新SpeedMonitor
   - TTS音量 → 调用AudioManager.setStreamVolume()
4. 参数变更后发送0x0001应答

### 2.3 透传进出站报告（0x0900）【P1】

#### 现场版实现

**进出站报告（type=6/7）：**
```java
// Generate808ReqPackage.generateReportStation()
消息体：
- DWORD: 线路号
- BYTE[6]: BCD时间
- BYTE: 方向（0上行/1下行）
- BYTE: 运营状态（0待班/1运营中/2完成）
- BYTE: type=6进站/7出站
- BYTE[10]: 站点名称（GB2312）
- WORD: 站点序号
- WORD: 本站上车人数
- WORD: 本站下车人数
- WORD: 车上总人数
```

**司机登录注销（type=1）：**
```java
消息体：
- DWORD: 线路号
- BYTE[6]: BCD时间
- BYTE: 方向
- BYTE: 运营状态
- BYTE: type=1
- BYTE[8]: 司机卡号（BCD）
- BYTE: 登录/注销标志（0登录/1注销）
```

#### Android11现状

**已有但不完整：**
```java
// Jt808LegacyMessages.createReportStation()
// 只生成0x0B02报站消息，未实现0x0900透传格式
```

#### 修复计划

1. 新增`Jt808TransparentMessage`类
2. 实现`create0x0900ReportStation(type, ...)`方法
3. 在StationBusinessModule站点变化时调用：
   ```java
   // 进站时发送type=6
   socketClientAdapter.send(channelName, 
       jt808Messages.create0x0900ReportStation(6, stationInfo, passengerCount), 
       traceId);
   // 出站时发送type=7
   ```
4. 在SignInBusinessModule签到时调用：
   ```java
   // 登录时发送type=1, flag=0
   ```

### 2.4 消息持久化与查看【P2】

#### 现场版实现

**MessageModel数据库表：**
```java
@Entity
public class MessageModel {
    @Id(autoincrement = true)
    private Long id;
    private String content;       // 消息内容
    private String time;          // 接收时间
    private int type;             // 消息类型（4=文本/7=调度）
    private boolean isRead;       // 已读标志
    private int priority;         // 优先级（紧急标志）
}
```

**消息查看页面：**
- `MessageFragment` - 消息列表
- `MessageDetailFragment` - 消息详情
