### 1.3 GPIO触发机制

**监听引脚**：
- **gpio1d1**：中门/倒车信号1
- **gpio1d0**：中门/倒车信号2

**触发逻辑表**（代码行：1373-1427）：

| gpio1d1 | gpio1d0 | operationStep | 触发状态 | 视频显示 |
|---------|---------|---------------|---------|---------|
| 1 | 0 | 1 | 倒车挂档 | 全屏倒车视频 |
| 0 | 1 | 2 | 中门打开 | 全屏中门视频 |
| 1 | 1 | 3 | 正常行驶 | 小屏DVR视频 |
| 0 | 0 | 4 | 中门+倒车 | 全屏倒车视频（倒车优先） |

**代码实现**：
```java
// MonitorThread.run() - 1373-1427行
int iGpioRead3 = GpioOperation.gpioRead("gpio1d1");
int iGpioRead4 = GpioOperation.gpioRead("gpio1d0");

if (iGpioRead3 == 1 && iGpioRead4 == 0) {
    operationStep = 1;  // 倒车
} else if (iGpioRead3 == 0 && iGpioRead4 == 1) {
    operationStep = 2;  // 中门
} else if (iGpioRead3 == 1 && iGpioRead4 == 1) {
    operationStep = 3;  // DVR小屏
} else if (iGpioRead3 == 0 && iGpioRead4 == 0) {
    operationStep = 4;  // 倒车优先
}

// 发送消息给主线程切换视频
handler.sendEmptyMessage(operationStep);
```

                TraceIds.next("home-monitor-gpio-unstable")

        return currentHomeMonitorMode != null ? currentHomeMonitorMode : HomeMonitorMode.DVR;
    }
    
    // GPIO信号稳定，解析视频模式
    int primary = primary2;

    // ... 后续逻辑
}

private class HomeMonitorThread extends Thread {
    private volatile boolean running = true;
    private final Handler mainHandler;
    
    public HomeMonitorThread(Handler handler) {
        this.mainHandler = handler;
    }
    
    @Override
    public void run() {
        while (running) {
            try {
                // 读取GPIO（带防抖）
                GpioReadResult result = cameraDvrBusinessModule.readGpioWithDebounce(
                    primaryGpioKey, secondaryGpioKey, "monitor-thread");
                
                if (result.isStable()) {
                    // 发送消息到主线程切换视频
                    mainHandler.post(() -> {
                        updateHomeMonitorMode(result.getPrimary(), result.getSecondary());
                    });
                }
                
                // 主循环间隔350ms
                Thread.sleep(350);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            }
        }
    }
    
    public void stopMonitoring() {
        running = false;
        interrupt();
    }
}

## 六、核心问题总结

### 🔴 根本原因

**测试反馈："首页的视频区域在特定的条件下才会放大（停靠站时，中门打开，倒车等）"**

**根本原因**：
1. **GPIO监听周期太长**：新壳每1秒才读取一次GPIO，而中门打开、倒车等动作可能持续时间很短（<1秒）
2. **缺少双重读取防抖**：单次读取容易受信号抖动影响，可能读到不稳定的值
3. **响应延迟高**：最高1秒的延迟导致用户感觉"有时候能放大，有时候不能"

**现场版的解决方案**：
- ✅ 独立线程350ms持续轮询GPIO
- ✅ 50ms双重读取验证，过滤信号抖动
- ✅ 响应延迟<400ms，用户感知即时
