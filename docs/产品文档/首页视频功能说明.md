## 一、功能概述

### 1.1 功能定位
首页视频功能是车载终端的核心显示功能，根据车辆状态（中门、倒车、正常行驶）自动切换视频显示模式，为司机提供实时视野辅助。

### 1.2 设计目标
- **即时响应**：GPIO状态变化后400ms内完成视频切换
- **稳定可靠**：50ms防抖机制，过滤信号干扰
- **优先级明确**：倒车 > 中门 > DVR，保证行车安全
- **资源管理**：切换前关闭所有摄像头，避免资源冲突

### 1.3 对标完成度
✅ **100%完成** - 所有关键参数与现场版M90完全一致

## 二、视频状态机

### 2.1 五种视频状态

| 状态ID | 状态名称 | 触发条件 | 视频显示 | 线路信息 | 班次信息 |
|--------|---------|---------|---------|---------|---------|
| **1** | 中门视频 | gpio1d1=0 且 gpio1d0=1 | ✅ 全屏中门摄像头 | ❌ 隐藏 | ❌ 隐藏 |
| **2** | 倒车视频 | gpio1d1=1 且 gpio1d0=0 | ✅ 全屏倒车摄像头 | ❌ 隐藏 | ❌ 隐藏 |
| **3** | DVR视频 | gpio1d1=1 且 gpio1d0=1 | ✅ 小屏DVR摄像头 | ✅ 显示 | ✅ 显示 |
| **4** | 倒车优先 | gpio1d1=0 且 gpio1d0=0 | ✅ 全屏倒车摄像头 | ❌ 隐藏 | ❌ 隐藏 |
| **5** | 关闭视频 | 无有效GPIO信号 | ❌ 无视频 | ✅ 显示 | ✅ 显示 |

### 2.2 状态转换时序图

```
初始状态（DVR小屏 - 状态3）
    ↓
中门打开（gpio1d1=0, gpio1d0=1）
    ↓
状态1：全屏中门视频
    ↓
中门关闭，挂倒车档（gpio1d1=1, gpio1d0=0）
    ↓
状态2：全屏倒车视频
    ↓
中门打开 + 倒车档（gpio1d1=0, gpio1d0=0）
    ↓
状态4：全屏倒车视频（倒车优先）
    ↓
正常行驶（gpio1d1=1, gpio1d0=1）
    ↓
状态3：小屏DVR视频（恢复默认）
```

### 2.3 优先级机制

**优先级顺序**（从高到低）：
1. **倒车视频**（最高优先级，安全第一）
2. **中门视频**
3. **DVR视频**（默认状态）

**冲突处理**：
- 当中门和倒车同时触发时，显示倒车视频（状态4：倒车优先）
- 保证倒车视频始终优先显示

## 四、防抖机制 ⭐ 核心

### 4.1 为什么需要防抖
**问题**：GPIO信号可能因为机械抖动、电磁干扰产生瞬时高/低电平变化  
**影响**：单次读取容易误判，导致视频频繁切换或不切换  
**解决**：50ms双重读取验证，过滤不稳定信号

### 4.2 50ms双重读取验证

**原理**：
1. 第1次读取GPIO状态
2. 等待50ms
3. 第2次读取GPIO状态
4. 只有两次读取**完全一致**才认为状态稳定

**代码实现**：
```java
// 对标现场版M90防抖机制：50ms双重读取验证（MainActivity.java 1354-1372行）
private HomeMonitorMode resolveHomeMonitorMode(@NonNull ShellConfig config) {
    // 第1次读取
    int primary1 = shellRuntime.getGpioAdapter().read(primaryKey, ...);
    int secondary1 = shellRuntime.getGpioAdapter().read(secondaryKey, ...);
    
    // 等待50ms（对标现场版：5次×10ms循环）
    try {
        Thread.sleep(50L);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
        return currentHomeMonitorMode != null ? currentHomeMonitorMode : HomeMonitorMode.DVR;
    }
    
    // 第2次读取
    int primary2 = shellRuntime.getGpioAdapter().read(primaryKey, ...);
    int secondary2 = shellRuntime.getGpioAdapter().read(secondaryKey, ...);
    
    // 两次读取必须完全一致才认为状态稳定（对标现场版1368-1372行）
    if (primary1 != primary2 || secondary1 != secondary2) {
        // GPIO信号不稳定，保持当前模式
        AppLogCenter.log(..., "GPIO信号不稳定，忽略切换", ...);
        return currentHomeMonitorMode != null ? currentHomeMonitorMode : HomeMonitorMode.DVR;
    }
    
    // GPIO信号稳定，解析视频模式
    int primary = primary2;
    int secondary = secondary2;
    // ... 后续逻辑
}
```

```java
private void updateHomeDvrPanel(ShellConfig config) {
    // 解析当前视频模式（带防抖）
    HomeMonitorMode mode = resolveHomeMonitorMode(config);
    
    // 应用视频模式（布局切换）
    applyHomeMonitorMode(mode);
    
    // 确定cameraKey
    String cameraKey = null;
    if (mode == HomeMonitorMode.MIDDLE_DOOR) {
        cameraKey = "middle_door";
    } else if (mode == HomeMonitorMode.REVERSE || mode == HomeMonitorMode.REVERSE_PRIORITY) {
        cameraKey = "reverse";
    } else if (mode == HomeMonitorMode.DVR) {
        cameraKey = "av_out";
    }
    
    // 切换摄像头
    if (cameraKey != null) {
        // 先关闭所有
        closeHomeMonitorPreview(traceId);
        // 再打开目标
        cameraDvrBusinessModule.openHomeMonitorCameraPreview(cameraKey, surfaceView, traceId);
        homeMonitorPreviewOpen = true;
        homeMonitorCameraKey = cameraKey;
    } else {
        closeHomeMonitorPreview(traceId);
    }
}
```

## 九、故障排查

### 9.1 视频不切换

**现象**：中门打开或倒车时，视频不切换

**排查步骤**：
1. 检查GPIO配置：
   - `debugReplay.monitorPrimaryGpioKey = "io1"`
   - `debugReplay.monitorSecondaryGpioKey = "io2"`
2. 检查GPIO模式：`gpio.mode = "real"`（真机环境）
3. 查看日志：搜索`GPIO信号不稳定`或`home-monitor-gpio`
4. 检查GPIO电平：使用万用表测量gpio1d1/gpio1d0电压
5. 检查摄像头配置：`camera.channels.*.cameraId`

**可能原因**：
- GPIO引脚配置错误
- GPIO模式为stub（模拟模式）
- GPIO电平极性反向
- 摄像头cameraId不正确

---

### 9.2 视频频繁闪烁

**现象**：视频不停切换，无法稳定显示

**排查步骤**：
1. 查看日志：搜索`GPIO信号不稳定`
2. 检查GPIO接线：是否存在虚焊、接触不良
3. 检查电源稳定性：电压波动可能导致GPIO抖动
4. 确认防抖机制：检查是否执行50ms双重验证

**可能原因**：
- GPIO信号线干扰
- 电源不稳定
- 防抖机制未生效

---

### 9.3 视频黑屏

**现象**：视频容器显示黑屏，无画面

**排查步骤**：
1. 检查摄像头权限：`AndroidManifest.xml`中是否声明`CAMERA`权限
2. 检查摄像头ID：确认cameraId与实际硬件对应
3. 查看日志：搜索`camera`或`preview`
4. 检查资源释放：是否存在摄像头未关闭导致占用

**可能原因**：
- 摄像头权限未授予
- cameraId不正确
- 摄像头资源被占用
- 摄像头硬件故障

---

### 9.4 响应延迟过高

**现象**：中门打开后1秒以上才切换视频

**排查步骤**：
1. 检查轮询周期：`HOME_MONITOR_GPIO_POLL_MS`是否为350
2. 检查线程状态：`homeMonitorGpioThread`是否正常运行
3. 查看日志：观察GPIO读取间隔时间
4. 检查系统负载：CPU占用是否过高

**可能原因**：
- 轮询周期配置错误（如1000ms）
- GPIO监听线程未启动
- 系统资源不足
