# CC808 报站平台站序排查组合清单

## 目标

确认设备发送的 CC808 报站是否能让线路监控页面的车辆沿站点序号移动。

固定测试车辆：`45678`

固定终端号：`18612345678`，帧内终端号应为 `018612345678`

固定线路：`L1`，平台线路号：`281`

平台当前线路表已确认：上行接口 `direction=0`，站点序号 `0..8`；站点 `stationCode` 全部为空。平台网页通过 WebSocket 的 `vehicleStatusList.stationIndex` 移动车辆。

## 记录规则

每次测试只改变一个变量。每次都记录：

- 测试编号、时间、APK 版本
- 线路、方向、内部 `stationNo`、`stationType`
- CC808 `0x0900` 原始 HEX 和消息体长度
- `0x0200` 原始 HEX、经纬度和定位有效位
- 平台 `0x8001` 应答的流水号、消息号和结果
- WebSocket 的 `vehicleName`、`lineStatus`、`stationState`、`stationIndex`、`gpsValue`
- 网页车辆 DOM 的 `left/top` 和网页统计信息

判定不能只看 `0x8001`。`0x8001` 只代表协议层收到并接受，不代表平台业务层已推进站序。

## 通过标准

- 协议层：帧完整、校验正确、终端号正确，平台应答结果为 `0`。
- 定位层：平台 `gpsValue` 与发送的坐标一致且持续更新。
- 站序层：平台 `stationIndex` 按预期变为目标站序，不回到 `0`。
- 网页层：WebSocket 数据变化后，车辆位置和站点状态同步变化。

## 新增证据：平台 API / H5 站序判定

来源：`G:\\调度平台API对接说明-报站-实时GPS-20230702.docx`，并与 `temp/DiagramMonitor.html`、`temp/LineDiagram.js` 对照。

- 平台通过 WebSocket `onDiagramLine` 推送 `vehicleStatusList`，网页直接使用其中的 `stationIndex`、`lineStatus`、`stationState` 和 `gpsValue`，网页本身不根据坐标重新计算站序。
- `lineStatus=0` 是上行，`lineStatus=1` 是下行；文档另列出 `2/3` 为起始方向状态，需在后续线路切换组合中单独验证。
- `stationState=0` 表示进站/站内，`stationState=1` 表示站外。上行绘制位置为：站内 `stationIndex * d`，站外 `(stationIndex + 0.5) * d`。
- 文档示例中的 `45678` 车辆 ID 为 `62cb4a4a0254248246dea32610051216`；当前网页也使用该 ID。
- 现场验证：当前 `45678` DOM 的 `left=67px`，上行线路起点的 `lineUp.left=75px`、第一站图标 `left=75px`，按 H5 公式可判定网页当前为 `stationIndex=0` 的起点位置。此前发送的纯 CC808 `0x0900` 已收到 `0x8001`，但网页仍保持该位置，说明协议层应答成功尚未证明平台业务层更新了站序。

因此后续每个测试组合必须同时记录三项：设备发送的 `0x0900` body 状态/站序/坐标、WebSocket 推送的 `stationIndex/stationState`、网页 DOM 的 `left/top`。只看到 `0x8001` 不判定通过。
